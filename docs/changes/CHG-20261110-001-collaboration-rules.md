# CHG-20261110-001：建立项目协作规范

- 日期：2026-11-10（Asia/Shanghai）
- 状态：已完成，不涉及上线
- 需求来源：用户要求“写项目协作规范”，并要求从后续变更开始记录修改原因、同步三语使用文档、同批发布和验收。
- 范围：仓库协作流程与记录模板，不涉及聊天模式锁定或位置跟随的实现。

## 为什么改

根目录 `AGENTS.md` 已要求记录功能变更、维护三语指南并同批发布，但尚缺少统一的记录位置、内容模板、设计决策与发布状态的区分，以及可复用的完成条件。

仅靠聊天记录或提交说明，后续维护者难以查明功能为什么改变，也容易把设计方案、本地完成和线上可用混为一谈。另有 `docs/` 整体忽略规则，会让新增记录无法随正常版本管理保存。

## 改了什么

- 新增 [项目协作规范](../../CONTRIBUTING.md)，明确授权范围、变更理由、重要决策、三语指南、验证、发布与完成条件。
- 保留 `AGENTS.md` 原有三条要求，增加完整规范入口及记录要求；在 `README.md` 增加入口。
- 新增 [变更记录模板](TEMPLATE.md)与 [ADR 模板](../decisions/TEMPLATE.md)，小改动保持简短，重要取舍单独记录。
- 在 `CHANGELOG.md` 添加本次记录链接。
- 为 `docs/changes/` 和 `docs/decisions/` 增加 Git 跟踪例外，其余既有文档忽略范围保留。

## 影响与边界

本次仅修改仓库文档和文档忽略规则，不改变页面、接口、模型提示词、业务存储或生产服务，不需要数据迁移。此前讨论的模式锁定与位置跟随仍是独立功能设计，本次不代表确认或实施该方案。

普通变更的理由写在变更记录中；只有重要、需长期解释的取舍才另建 ADR，避免每个小修都增加重复文档。

## 验收与结果

- 已核对 5 份协作文档中的 17 个仓库链接，以及编号、规则与入口的一致性，结果通过。
- 已核对 5 个文档路径可以正常跟踪，并验证 5 个既有文档、敏感数据或运行环境路径仍被忽略，结果通过。
- 已审阅本次补丁与改动范围，保留工作区已有修改。格式检查按仓库已有 CRLF 换行处理，不批量改写历史日志的换行。
- 本次不运行业务测试：没有修改业务代码、页面或用户可用行为。

## 使用文档与更新日志

中文、日文、英文 `/guide` 均不适用：这是开发协作规范，不是用户功能变化，因此不向站内使用指南加入开发流程。后续用户可见功能必须遵守三语同步要求。

更新日志入口：[CHANGELOG.md](../../CHANGELOG.md) 的未发布区域。

## 发布

不涉及生产上线，没有上传文件、重启服务或修改线上数据。未来功能发布按规范将功能、变更记录、使用指南和更新日志作为同一批次验收。

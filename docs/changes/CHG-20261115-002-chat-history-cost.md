# CHG-20261115-002 · 降低聊天历史统计成本

- 状态：已发布、已验收。
- 范围：A14 的长历史查询、搜索和聊天轮询测量。

单聊和群聊历史接口原先在同一个聚合中计算消息数和最小、最大 ID，每轮请求逐行处理。现在依然用一条 SQL，但将三项拆成独立子查询，使 SQLite 能对 COUNT(*) 使用专门的计数路径，最小和最大 ID 各自使用主键端点。结果格式和分页条件相同。无需索引迁移。中、日、英指南不适用，因为操作方法、结果和可用选项都相同。

从项目根运行 `python3 docs/changes/a14-20261115/queries.py` 与 `.venv/bin/python docs/changes/a14-20261115/header.py` 可重跑。会话库使用合成数据，10,000 或 100,000 条记录，每条约 180 个汉字。每项先预热、再计时 21 次。搜索计入 SQLite 读取和 JSON 序列化，不含网络与浏览器渲染。

| 项目 | 结果 |
| --- | --- |
| 100,000 条，按 ID 查无新增 | 中位 0.004 ms，SQLite 使用整数主键范围查询 |
| 100,000 条，消息数与前后边界 | 中位 20.367 → 12.827 ms，约降 37%。空库、单条、非连续与大 ID 四组比对结果一致 |
| 100,000 条，排序取最近 21 条模型上下文 | 无时间索引中位 195.799 ms，临时时间索引试验约 0.029 ms |
| 100,000 条，共同词搜索 | 中位 418.074 ms，合成结果全命中，序列化约 59.5 MB |
| 未读数，5 / 25 / 100 个会话 | 每轮分别打开 4 / 24 / 99 个数据库，中位约 0.49 / 2.82 / 13.03 ms，模拟已保存 ID 游标 |

结果是本机容量实验，未采样生产耗时。无索引计数仍随数据量增长。时间索引只在合成库试验，本批不修改索引。搜索其余工作可按实际日志或用户反馈再决定，首选限制单次结果并支持分页。未读统计有按会话增长的成本，当前证据不足以改动刷新策略。
